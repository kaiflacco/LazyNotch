# LazyNotch — Clean-Room & IP Guardrails

## Objective

Build an independent product that implements comparable observable functionality without copying protected implementation materials or creating confusing branding.

## Allowed

- observing public product behavior
- documenting UI states
- measuring screenshots made during legitimate use
- studying public documentation
- implementing original Swift/SwiftUI/AppKit code
- creating original artwork
- using Apple system fonts/SF Symbols
- using compatible open-source dependencies

## Do not

- copy proprietary source code
- extract proprietary app assets
- decompile binaries to obtain implementation details
- copy logos or artwork
- reuse proprietary strings unnecessarily
- represent LazyNotch as official, affiliated, or endorsed

## Reference versus implementation

The research folder may say:

> "Reference behavior observed in NotchNook."

The implementation should say:

> "LazyNotch behavior."

The source code should contain LazyNotch product terminology.

## Open-source references

For any third-party project:

1. record repository URL;
2. record commit/tag;
3. inspect license;
4. record dependency/license obligations;
5. isolate reused code;
6. document modifications.

## Visual parity

Preserve functional and interaction concepts while using original LazyNotch:

- branding
- icons
- illustrations
- copy
- logo
- product naming

Exact proprietary artwork should not be copied.

This is engineering guidance, not legal advice. Obtain legal review before commercial distribution if the product intentionally targets very close visual parity.
